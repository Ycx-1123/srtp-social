# SOCI-AI 单文件分发与本机会话历史设计

日期：2026-09-27。状态：用户已确认聊天方案及本书面规格（回复“确认规格”）；进入实施计划阶段，尚未开始实现。

## 给使用者看的摘要

- 对外提供一个可直接运行的 Windows x64 EXE，不要求用户接收项目源码、安装 Python 或联网下载模型。
- 每次开始检测创建独立会话；结束检测或正常关闭软件时自动保存，运行中每 5 秒保存一次进度。
- 保存会话时间、时长、SBI 曲线与线索、确认字幕、事件和复盘建议；不保存原始视频、照片、录音或未确认字幕。
- 在现有“会话回顾”页选择历史会话，复用当前渐变曲线和简短悬停标签；实时主界面保持不变。
- 删除前确认，只删除选中的已结束会话；不会删除其他会话或用户已经导出的文件。
- 历史放在当前 Windows 用户的本机应用数据目录。移动或更换 EXE 不会使历史消失；不同 Windows 账号默认不共享。
- 单文件打包不是加密，不能承诺防反编译。记录不上传，但本地数据库不是加密保险箱。

## 1. 目标与范围

解决两项已确认需求：只分发一个可运行 EXE；在本机持续保存、查看和逐条删除使用记录。采用现有原生 Qt 界面、模型、Bias 场景库和评分机制，不重做识别模型、评分、生命树、语料或现有图表。

本次不增加云同步、账号系统、跨 Windows 用户共享、原始媒体录制、会议平台适配、代码加密、全量清空按钮或自动导入其他目录中的文件。

同一电脑上的“全部记录”限定为：该 Windows 账号使用新版本产生并成功保存的会话。不追溯恢复旧版只在内存中存在且已经丢失的数据。旧版本运行文件夹和手动导出文件保留，不自动移动、删除或合并。

## 2. 已核实的现状

- `build_desktop.py` 使用 PyInstaller `--onedir`，模型、词库、Python 运行时和 DLL 位于分发文件夹；单独复制当前 EXE 会缺少依赖。
- `resource_root()` 已区分源码目录与冻结程序的 `_MEIPASS`，可继续加载单文件内的只读资源。
- `output_root()` 目前是 EXE 同目录下的 `data/desktop`，移动 EXE、只读位置和后续单文件模式需要解耦。
- `DesktopSession.latest_report` 保存内存快照；`__main__.py` 只有手动导出，没有自动持久化。
- 实时刷新会更新回顾页；增加历史选择后必须防止历史详情被当前会话覆盖。
- 导出目前读取 `session.latest_report`，需要改为导出用户当前查看的报告。

## 3. 方案取舍

已选定“单文件直接运行”，不采用“单个安装器、安装后多个文件”的替代方案。单文件内置现有模型和语言资源，首次及每次启动的解压开销需要实测，不能许诺与文件夹版相同的启动速度。

开发和诊断可以保留文件夹式构建以方便排错；给用户的正式交付只有新的单文件 EXE。新产物输出到独立目录，不覆盖当前可运行的文件夹式版本。

## 4. 资源与用户数据分离

只读模型和语料继续从 `resource_root()` 读取，冻结程序由 `_MEIPASS` 提供。不得将历史、日志或导出结果写进临时解压目录。

生产数据目录固定为 `%LOCALAPPDATA%/SOCI-AI-Desktop`，数据库为 `history.sqlite3`，日志位于 `logs`，默认导出目录为 `exports`。缺少环境变量时采用当前用户的 Windows 本地应用数据路径，不回退写入软件所在文件夹。路径不可用时明确提示持久化失败，而不是换到未知目录静默保存。

保持现有单实例锁及摄像头、麦克风的安全释放机制。历史仅属于当前 Windows 账号；不创建全机共享位置，不要求管理员权限，不改系统设置。

构建自检、模型自检、离屏界面自检及自动化测试通过明确的测试目录或路径注入隔离；不向真实用户历史写入合成测试会话，也不将开发者日志或历史装进交付 EXE。

## 5. 存储模块与持久化格式

新增独立历史模块，使用 Python 标准库 SQLite，无需新在线服务。存储层接收可序列化报告，不引用摄像头、麦克风、模型或 Qt 控件。

数据库采用版本化 schema。每条记录包括：随机会话 ID、带时区的开始时间、结束时间、更新时间、会话状态、时长、平均和峰值 SBI、报告格式版本、应用版本以及完整报告 JSON。会话时间排序加索引。

状态区分“进行中”“已结束”“中断”。报告保存当前已经形成的 `history`、`events`、确认 `transcripts`、`advice`、`moments`、统计、语料版本、来源与边界说明。逐点线索和建议随快照保存，查看历史时不按新版规则重新推断或改写当时结果。

序列化限制在现有报告的允许字段，不接收图像数组、图像文件、音频波形、设备流对象或临时转写。保存的数据范围与当前报告自身的采样/保留策略一致，不声称记录了所有原始摄像头帧或所有推理输出。

## 6. 生命周期与实时性

成功启动一次检测后生成新的随机 ID，创建“进行中”记录。即使设备没有产生有效信号，也保留这次使用及实际缺失状态，不伪造分数。

运行时每 5 秒提交最新报告快照。采用单个后台存储工作线程，线程内持有数据库连接；写盘和 JSON 编码不占用图像采集、语音解码线程。普通检查点允许合并为该会话的最新快照，不无限积压。UI 通过结果队列或信号获知保存结果，不等待写盘才显示视频或评分。

主动结束会话或正常关闭窗口时，提交最终快照并标记“已结束”；同时结束、随后关闭不会新增第二条记录。新会话不会覆盖旧会话。退出时需等待最终写入和本应用设备线程完成安全释放；保存失败时提供保留窗口/重试或明确放弃未保存内容的选择，不假装保存成功。

崩溃或强制结束后，下次启动将遗留的“进行中”记录标为“中断”，展示最后成功写入的快照。每 5 秒检查点是正常可写条件下的设计目标，不承诺断电、磁盘故障时仍保存最后 5 秒。

所有检查点和终结操作只更新已经创建的会话，不对不存在的 ID 自动重新插入；完成后不接受旧检查点回写为进行中。最终化可重复调用但结果幂等。此约束防止晚到队列任务复活已删除记录或覆盖最终报告。

## 7. 回顾页交互

保留三项导航和实时主界面。在“会话回顾”顶部增加历史选择区、刷新及删除入口。按时间倒序显示日期时间、时长、平均/峰值 SBI 和状态，使用紧凑的中文样式，不增加英文说明和无意义事件清单。

首次启动没有历史时显示明确空状态；存在历史时，回顾页默认加载最近一次保存记录。进行检测时可以切换到“当前会话”或某条历史；只有选择当前会话才接受实时回顾刷新。查看历史不启动摄像头、不修改实时评分，也不被后台刷新抢回当前会话。

历史详情复用现有曲线、逐点悬停标签、关键时刻、建议和字幕展开功能。异步读取返回时核对选择令牌，避免快速切换导致旧返回覆盖新选择。

“导出会话报告”导出正在查看的报告，无论是历史还是当前会话。切换新会话、删除历史或读取失败时同步按钮状态，不能误导出上一条数据。

删除仅允许选中已结束或中断的具体会话；当前正在检测的记录不可删除，先结束会话。确认框展示会话日期与时长，并告知删除影响范围和不可从应用内撤销。数据库事务删除单个 ID，成功后刷新列表并选择邻近记录，没有剩余记录时清空详情。失败时保留当前条目和选择，不显示虚假的成功状态。已单独导出的文件不受影响。

删除为应用层逻辑删除记录，不保证存储介质上的取证级不可恢复；不承诺安全擦除 SSD 或其他软件备份。

## 8. 异常与兼容处理

- 数据目录不可写、磁盘满、数据库锁定：显示中文保存状态和具体失败，不阻塞实时自检；失败快照保留用于重试或手动导出。
- 单条报告 JSON 损坏：只标记该条详情不可读取，列表和其他会话仍可使用；不删除原始数据。
- 数据库损坏或版本比程序新：不自动清空、重建覆盖或降级；禁用历史写入并提示保留数据库、检查版本。检测可继续，但必须明确本次不能自动保存。
- schema 升级：事务式处理，失败回滚，保留原记录；不因升级删除会话。
- 异步任务取消、历史选择变化、重复结束和退出：通过 ID、终态和选择令牌防止覆盖或复活。
- 单文件资源缺失或模型加载失败：维持实际错误状态，不伪造字幕、分数、成功自检或摄像头画面。

## 9. 修改边界

涉及文件：新增历史存储/协调模块及其测试；修改 `resources.py`、`__main__.py`、`ui.py`、`build_desktop.py`；按实际需要补充 `session.py` 的时间/快照元数据；更新桌面使用与打包说明。

不改现有视觉算法、语义库、融合权重或树的评分驱动逻辑。不覆盖和删除用户现有文件夹式安装、手动导出报告、模型研究目录或其他软件进程。

## 10. 验收与交付

1. 存储测试：两条以上独立会话、关闭并重开、最终化幂等、中断恢复、空会话、事务删除、失败与损坏处理、不同数据目录隔离。
2. 协调测试：检查点合并、慢写盘不阻塞实时刷新、终结优先、终态不被旧快照覆盖、删除后不复活、关机等待和错误反馈。
3. 界面测试：选择历史、查看渐变曲线及不同原因标签、导出所选报告、取消/确认删除、删除最后一条、实时刷新不覆盖历史详情、尺寸适配。
4. 回归：运行既有桌面测试，确保摄像头预览、中文流式识别、建议阅读停留、单实例和安全退出行为未退化。
5. 冻结自检：在隔离目录中运行文件模型自检及离屏界面自检，不打开设备、不接触真实用户历史。
6. 分发验证：把新 EXE 单独复制到不含 `_internal`、项目源码和外部模型的测试目录，以不同工作目录启动，并验证内置模型和界面；跨进程验证历史可加载和逐条删除。测量单文件启动耗时和文件大小，不虚报硬件兼容性。
7. 交付独立单文件 EXE、版本与校验摘要、简短使用提示；旧运行包保留作为回退。真实摄像头/麦克风测试及另一台电脑的兼容性与文件自检分开报告。
