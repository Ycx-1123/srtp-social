# SOCI-AI 实时感知与生命树界面设计规格

日期：2026-09-25
状态：待用户书面确认

## 1. 目标与产品定位

SOCI-AI 的主入口必须分析摄像头前使用者本人的真实言行，而不是观察谈话对象，也不是默认播放预设场景。系统面向会议、面试、课堂和交流训练等场景，帮助使用者发现自己无意识产生的皱眉、不友好语气、刻板印象表达等细微社交偏差。

实时使用者不应阅读大段文字。主界面以一棵程序化动态生命树承载自我状态：颜色、姿态、叶片、花朵、粒子和生长/凋谢共同表达当前社交友好度、微冒犯风险及修正趋势。完整数值、时间线、模态贡献、实时转录和研究证据留到详情区与会后复盘。

系统表达的是“我当前可观察到的社交行为及微冒犯风险”，不是对人格、道德或心理健康作诊断。证据不足时必须保持中性状态并说明原因。

## 2. 已确认的关键原则

1. 默认使用真实摄像头和麦克风；演示场景仅作为明确标注的“备用回放”。
2. 所有推理优先在本机完成，基础模式不依赖云端 API。
3. 默认不持久化原始视频、照片或录音，只保存经处理的结构化特征、事件和会话摘要。
4. 任一模态缺失或模型不可用时降低置信度，绝不用模拟数据偷偷补齐。
5. 轻薄本优先：AI 推理低频运行，树动画与推理解耦，保证视觉持续流畅。
6. 实时页只显示一句状态和至多一句行动建议；详细数据通过抽屉或复盘页按需查看。
7. 第一版采用单人自检假设：近距离主讲者默认是摄像头前的使用者本人。声纹注册与多人说话人分离只预留扩展接口，不作为已实现能力。
8. 自拍画面始终提供可见入口，实时分析时必须显示人脸检测框；“正在监听/正在转写/正在分析”状态必须与真实处理状态绑定。

## 3. 总体架构

采用“浏览器采集 + 本地 FastAPI 推理 + Canvas 生命树”的架构。

### 3.1 浏览器端

- 使用 `MediaDevices.getUserMedia` 获取真实摄像头和麦克风权限。
- 摄像头预览在授权和校准阶段突出显示；分析开始后保留清晰可见的自拍卡片，并在人脸位置绘制检测框、状态标签和视觉置信度。
- 以约 2–4 FPS 抽取低分辨率 JPEG/WebP 帧提交给本地后端。
- 使用 Web Audio API 实时提取音量、活动比例、停顿和节奏等声学特征，并显示真实麦克风波形和采集状态。
- 按短音频窗口调用本地 SenseVoice 进行中文转写与语音情绪分析；界面显示“正在监听、正在转写、正在分析”三个真实阶段和最新转录文本。原始音频窗口处理后即释放，不持久化。
- 使用 Canvas 2D 绘制程序化生命树，目标动画刷新率为 60 FPS。树从后端状态平滑插值，不因单帧预测发生突变。

### 3.2 本地后端

- FastAPI 提供能力检测、会话启停、视频帧分析、声学特征提交、实时状态查询和会后报告接口。
- `LiveSessionRuntime` 管理真实会话，不与备用回放运行时混用。
- `YoloEmotionAdapter` 懒加载现有约 3 MB 的 YOLOv8 分类权重，使用 OpenCV 检测/裁剪人脸，并在 CPU 上输出表情概率、置信度和人脸边界框。视觉风险关注皱眉、厌恶、愤怒、紧绷等可观察信号及其持续变化。
- 声学模块结合浏览器特征与本地 SenseVoice，输出音量突增、语速、停顿、语气压力、语音情绪和实时转录。SenseVoice 不可用时仍保留基础声学分析，但明确标记“转写不可用”。
- 语义模块分析转录文本中的贬低、排斥、刻板印象和隐性偏见表达，例如“女生不适合学工科”，同时保留触发片段和可解释类别。
- 融合层沿用可解释 SBI 思路，综合视觉、声学与语义风险，并使用证据门控、时间平滑、迟滞和修正识别，避免界面频繁抖动。

### 3.3 数据流

1. 用户进入实时页，系统先检测浏览器媒体能力、后端状态和本地模型。
2. 用户点击“开始实时感知”，浏览器请求摄像头和麦克风权限。
3. 真实视频帧进入视觉适配器；麦克风特征和短音频窗口进入声学/转写适配器，转录文本进入语义适配器。
4. 后端按时间窗口融合最新有效证据，输出自我微冒犯风险、社交友好度、趋势、置信度、证据状态和一句短建议。
5. 浏览器高频渲染树动画，并在新状态到达时以阻尼插值过渡。
6. 用户停止后，后端只持久化结构化会话记录并生成复盘内容。

## 4. 生命树视觉系统

生命树必须是产品主视觉，而不是普通图表的装饰。

### 4.1 构成

- 多层递归枝干：主干稳定、末端枝条随微冒犯风险产生不同幅度的风动。
- 发光叶片粒子：密度、饱和度、脱落概率由状态驱动。
- 花苞与花瓣：在友好或修正状态出现；高风险持续时逐渐凋谢。
- 根部光晕和上升粒子：表达系统仍在持续感知，而非静态图片。
- 柔和暗色背景、局部雾化和微弱星尘，保持答辩投影环境中的清晰度。

### 4.2 状态映射

| 状态 | 颜色与形态 | 动效 | 文本 |
| --- | --- | --- | --- |
| 未开始/证据不足 | 银蓝、枝干舒展但叶片稀疏 | 缓慢呼吸 | 正在观察/等待有效证据 |
| 友好平稳 | 翡翠绿、树冠饱满、花苞开放 | 柔和摆动、粒子向上 | 当前表达友好平稳 |
| 细微信号 | 绿到琥珀渐变、树冠轻微收拢 | 风动加快、少量落叶 | 检测到轻微偏差信号 |
| 风险累积 | 琥珀到暖橙红、枝条下垂 | 光脉增强、花瓣和叶片脱落 | 微冒犯风险正在累积 |
| 主动修正 | 青绿沿枝条重新生长、嫩芽出现 | 叶片回生、花苞重新开放 | 表达方式正在改善 |

颜色和形态均采用连续数值驱动。界面不得因短暂噪声瞬间从繁茂切换为枯萎。

### 4.3 实时信息层级

- 主视区：生命树、当前综合分数、简短状态和趋势短语。
- 自拍卡片：真实视频、人脸检测框、视觉分析状态和置信度，始终可见或一键展开。
- 语音卡片：实时波形、监听/转写/分析指示器和最新一句转录。
- 次级信息：设备状态、隐私提示、开始/停止按钮和一句行动建议。
- 可折叠详情：微冒犯风险、社交友好度、语气压力、视觉紧张度、语义偏差及各模态贡献。
- 会后复盘：完整时间线、转录、关键片段、融合解释、干预记录和报告导出。

## 5. 接口与组件边界

建议新增以下独立模块：

- `soci_ai/live/domain.py`：实时会话、设备、证据和树状态的数据模型。
- `soci_ai/live/vision.py`：OpenCV 人脸处理与 YOLOv8 推理适配器。
- `soci_ai/live/audio.py`：浏览器声学特征校验、短音频处理与 SenseVoice 适配。
- `soci_ai/live/semantics.py`：转录文本的微冒犯类别分析与证据解释。
- `soci_ai/live/runtime.py`：会话生命周期、窗口融合、持久化协调。
- `soci_ai/live/api.py`：实时能力、会话、视频帧和声学特征接口。
- `web/js/media.js`：权限、摄像头采样、Web Audio 特征提取。
- `web/js/tree.js`：生命树生成、动画和状态插值。
- `web/js/live.js`：实时页控制器；原有脚本继续负责复盘页。

核心接口：

- `GET /api/live/capabilities`
- `POST /api/live/sessions`
- `POST /api/live/sessions/{id}/frame`
- `POST /api/live/sessions/{id}/audio-features`
- `POST /api/live/sessions/{id}/audio-chunk`
- `GET /api/live/sessions/{id}/state`
- `POST /api/live/sessions/{id}/stop`

## 6. 失败与降级处理

- 摄像头或麦克风拒绝授权：明确显示设备不可用，树保持银蓝中性，不进入备用场景。
- 未检测到人脸：显示“画面中暂未检测到清晰人脸”，移除检测框且不输出视觉行为结论。
- 环境安静：显示“当前未检测到有效语音”，不将沉默自动解释为微冒犯。
- YOLO 权重缺失或加载失败：后端能力状态标红，允许声学单模态运行并标记证据有限。
- SenseVoice 不可用：基础声学模式继续运行，明确显示“实时转写不可用”，绝不伪装为正在转写。
- 帧处理过慢：主动降低采样频率和分辨率，Canvas 动画不受推理阻塞。
- 网络连接短暂中断：前端保留最近可信状态并逐渐回到中性，而不是冻结在高风险状态。

## 7. 性能与隐私预算

- 默认视频采样 3 FPS，输入最长边约 480 像素，可根据推理耗时自适应降至 2 FPS。
- 同一时刻只分析最大人脸区域，避免轻薄本多目标推理压力。
- YOLOv8 CPU 推理按单请求串行化，防止积压；过期帧直接丢弃。
- Canvas 树不依赖后端帧率，目标 50–60 FPS；低性能设备自动降低粒子数量。
- 原始帧只在内存中短暂存在，处理后释放；不写入会话数据库。
- 原始音频在基础模式不离开浏览器，也不落盘。
- 启用转写时只传输本地短音频窗口，推理完成后释放；会话库仅保存转录文本与结构化特征。

## 8. 测试与验收

### 8.1 自动化测试

- 视觉适配器使用合成图像和假模型进行自动化测试：有人脸、无人脸、边界框、模型缺失和推理异常。真实运行仍使用摄像头和实际 YOLOv8 权重。
- 声学特征验证测试：合法输入、异常值、静音和超时。
- 转写与语义测试：真实状态机、文本返回、刻板印象样例、解释证据和 SenseVoice 缺失降级。
- 实时运行时测试：证据门控、状态平滑、风险累积、主动修正、断流回中性。
- API 测试：会话生命周期、无权限/无设备语义、无原始媒体持久化。
- 前端契约测试：默认入口为实时感知，备用回放清晰标注，Canvas 与媒体模块存在。

### 8.2 人工验收

1. 在真实浏览器中授权摄像头和麦克风，可看到自拍画面、真实人脸框、波形及设备状态。
2. 人脸进入/离开画面时，检测框和证据状态正确变化且不出现模拟结果。
3. 对着麦克风说中文时，监听、转写、分析状态按真实流程变化，并显示识别文本。
4. 皱眉、语气变强或说出测试用刻板印象语句时，相应模态指标与综合风险发生可解释变化。
5. 树可在中性、繁茂、细微信号、风险累积和主动修正之间连续过渡，动画美观且无明显卡顿。
6. 停止会话后能查看详细复盘；数据库中不存在原始图像和音频文件。
7. 断开模型或拒绝权限后，界面能够诚实降级并给出修复提示。

## 9. 实施范围与迁移

现有模拟场景、SBI 融合、干预策略、会话存储和复盘视图继续复用，但产品导航与默认页改为面向使用者本人的真实自检。模拟运行入口更名为“备用回放”，显示醒目标识，专用于无设备或答辩应急演示。

本次实现不承诺医学级情绪识别、不进行身份识别、不实现云端多人会议接入、声纹注册或多人说话人分离，也不保存可回放的原始媒体。系统为这些增强能力预留适配器接口；答辩中应表述为“已完成技术方案与扩展接口设计，当前演示采用单人低算力模式”，不得表述为已经完成真实能力。
