# SOCI-AI Studio 架构

## 产品边界

SOCI-AI 观察的是摄像头前使用者本人的社交行为，不是谈话对象的心理状态。它帮助使用者发现皱眉、语气压力、群体刻板印象和贬低表达等可能无意识出现的微冒犯，并通过低认知负担的生命树及时提醒。

第一版是单人自检：麦克风中的近距离主讲者默认是本人。声纹注册和多人说话人分离只保留适配器边界，尚未实现。

## 实时数据流

```text
浏览器真实设备
  ├─ MediaDevices 摄像头 → 3 FPS JPEG/WebP → OpenCV 最大人脸 → YOLOv8 表情分类
  ├─ Web Audio → RMS / peak / speech ratio / 停顿 → 声学压力
  └─ 16 kHz PCM 断句 → SenseVoice → 中文转录与语音标签
                                            │
                                            ▼
                         中文微冒犯规则：刻板印象 / 贬低 / 排斥
                                            │
                ┌───────────────────────────┘
                ▼
可靠度门控 q × 模态权重 w × 新鲜度衰减
                │
       跨模态协同 Γ + 泄漏积分 E(t)
                │
                ▼
SBI / 友好度 / 模态贡献 / 最小充分提示 / TreeState
                │
        ┌───────┴────────┐
        ▼                ▼
Canvas 动态生命树      SQLite 结构化会话记录
50–60 FPS              不包含原始音视频
```

## 组件边界

- `soci_ai/live/domain.py`：实时状态、人脸框、音频、转录与树状态契约。
- `soci_ai/live/capabilities.py`：只读能力发现，不导入重模型。
- `soci_ai/live/vision.py`：懒加载 YOLOv8，只处理画面中面积最大的人脸。
- `soci_ai/live/audio.py`：浏览器声学特征校验、PCM 静音门控与 SenseVoice 内存推理。
- `soci_ai/live/semantics.py`：可解释中文微冒犯模式。
- `soci_ai/live/runtime.py`：会话生命周期、最新帧优先、measured 融合和树状态映射。
- `soci_ai/live/api.py`：本地实时 API、结构化错误与运行时注册表。
- `web/js/media.js`：真实媒体权限、采样、波形、VAD 和 PCM16 编码。
- `web/js/tree.js`：程序化枝干、发光叶片、花朵、落叶与恢复生长。
- `ShowcaseRuntime`：与真实运行时隔离，只服务明确标注的备用回放。

## 性能策略

- 摄像头默认 3 FPS、最长边 480 像素；帧处理繁忙时只保留最新待处理帧。
- YOLOv8 固定 CPU，避免答辩轻薄本依赖 CUDA。
- SenseVoice 首次真实语音到来时才懒加载，缺失时不阻止基础模式启动。
- Canvas 渲染与后端推理解耦，并依据最近 60 帧耗时采用 1200、700、360 三级粒子预算。
- 所有模型调用通过工作线程执行，不阻塞 FastAPI 事件循环。

## SBI 与干预

每个模态先依据风险值、置信度和新鲜度形成门控贡献。至少两个独立模态在同一时间窗有效时加入协同项；泄漏积分保留持续弱信号并让孤立噪声自然衰减。实时状态使用 `MEASURED` provenance，备用回放使用 `SIMULATED`。

干预遵循最小充分原则：证据不足时保持中性；信号持续后给出针对行为的短建议；风险降低后显示恢复生长。系统不对使用者人格、动机或心理健康作判断。

## 隐私

浏览器直接持有设备权限。原始帧与 PCM 只在本机内存短暂存在，API 持久化函数只接收派生状态对象，因此媒体字节没有进入 SQLite 的调用路径。会话记录包含结构化特征、转录、SBI、解释和提示，可用于会后复盘。
